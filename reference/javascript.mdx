## Overview

The JavaScript code in `particula.js` handles two main responsibilities: controlling the music player interface and configuring the particle animation system. The code combines vanilla JavaScript for DOM manipulation with the particles.js and stats.js libraries for visual effects.

## Music Player Logic

The music player provides play/pause controls and volume adjustment through a clean event-driven architecture.

### DOM Element References

First, the script gets references to all necessary DOM elements:


### Play/Pause Toggle

The play/pause button uses an event listener to toggle audio playback:

```javascript
btnPlayPausa.addEventListener('click', () => {
    if (audio.paused) {
        audio.play();
        icono.className = 'fas fa-pause';
    } else {
        audio.pause();
        icono.className = 'fas fa-play';
    }
});
```

<Steps>
  <Step title="Check Audio State">
    The `audio.paused` property returns `true` if audio is currently paused
  </Step>
  <Step title="Toggle Playback">
    Calls `audio.play()` or `audio.pause()` based on current state
  </Step>
  <Step title="Update Icon">
    Changes the Font Awesome class to show the appropriate icon (play ↔ pause)
  </Step>
</Steps>

<Note>
The icon classes `fas fa-play` and `fas fa-pause` come from Font Awesome 6.0, which is loaded in the HTML head.
</Note>

### Volume Control

The volume slider uses an input event listener for real-time updates:

```javascript
controlVolumen.addEventListener('input', (e) => {
    audio.volume = e.target.value;
});
```

<Accordion title="Volume Control Details">
  **How it works:**
  
  - The range input in HTML has `min="0"`, `max="1"`, `step="0.1"`, and `value="0.5"`
  - The `input` event fires continuously as the user drags the slider
  - `e.target.value` retrieves the current slider value (0.0 to 1.0)
  - `audio.volume` accepts values from 0 (muted) to 1 (full volume)
  - Default volume starts at 0.5 (50%)
</Accordion>

<Tip>
Using the `input` event instead of `change` provides instant feedback as the user drags the slider, rather than waiting until they release it.
</Tip>


### Movement Configuration

```javascript
"move": {
  "enable": true,
  "speed": 6,
  "direction": "none",
  "random": false,
  "straight": false,
  "out_mode": "out",
  "bounce": false,
  "attract": {
    "enable": false,
    "rotateX": 600,
    "rotateY": 1200
  }
}
```

#### Movement Properties Explained

| Property | Value | Meaning |
|----------|-------|---------|
| `enable` | true | Particles move continuously |
| `speed` | 6 | Movement speed (higher = faster) |
| `direction` | "none" | Particles move in random directions |
| `random` | false | Movement isn't erratic (smooth paths) |
| `straight` | false | Particles can change direction |
| `out_mode` | "out" | Particles leave viewport and reappear on opposite side |
| `bounce` | false | Particles don't bounce off edges |

<Note>
The `out_mode: "out"` creates a seamless infinite effect as particles exit one side and enter from the other.
</Note>

## Stats.js Integration

The stats display shows real-time particle count and performance metrics:

```javascript
var count_particles, stats, update;

stats = new Stats;
stats.setMode(0);
stats.domElement.style.position = 'absolute';
stats.domElement.style.left = '0px';
stats.domElement.style.top = '0px';
document.body.appendChild(stats.domElement);
```

<Steps>
  <Step title="Initialize Stats">
    Create new Stats instance with mode 0 (FPS display)
  </Step>
  <Step title="Position Stats Panel">
    Set absolute positioning at top-left corner (0, 0)
  </Step>
  <Step title="Add to DOM">
    Append the stats DOM element to the document body
  </Step>
</Steps>

### Particle Counter

```javascript
count_particles = document.querySelector('.js-count-particles');

update = function() {
  stats.begin();
  stats.end();
  
  if (window.pJSDom[0].pJS.particles && window.pJSDom[0].pJS.particles.array) {
    count_particles.innerText = window.pJSDom[0].pJS.particles.array.length;
  }
  
  requestAnimationFrame(update);
};

requestAnimationFrame(update);
```

<Accordion title="Update Loop Breakdown">
  **The update function:**
  
  1. `stats.begin()` and `stats.end()` - Measure frame timing for FPS
  2. Access the particles array from the particles.js instance
  3. Update the particle count display with current array length
  4. `requestAnimationFrame(update)` - Schedule next update (60 FPS)
  
  This creates a smooth animation loop synchronized with the browser's repaint cycle.
</Accordion>

<Note>
The particle count displays in the `.js-count-particles` element, which should be present in the HTML for this to work without errors. The current HTML doesn't include this element, so the counter won't display.
</Note>

For better performance on mobile devices, consider:
- Reducing particle count to 40-50
- Decreasing movement speed to 3-4
- Disabling stats.js in production

```html
<!-- Load libraries first -->
<script src="https://cdn.jsdelivr.net/particles.js/2.0.0/particles.min.js"></script>
<script src="https://threejs.org/examples/js/libs/stats.min.js"></script>

<!-- Then load application code -->
<script src="particula.js"></script>
```

<Warning>
The application code must load after the libraries. If `particula.js` loads first, `particlesJS` and `Stats` will be undefined, causing errors.
</Warning>
